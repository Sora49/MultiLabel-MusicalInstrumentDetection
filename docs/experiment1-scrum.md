# Experiment 1: Agile and Scrum Demo

## Project
Multi-Label Musical Instrument Detection

## Objective
Apply Scrum practices to organize work on the existing instrument-detection project.

## Product Goal
Provide a Streamlit app that identifies which of five target instruments are present in an uploaded audio file.

## Scrum Roles
- Product Owner: Me — defined the project goal and priorities.
- Scrum Master: Me — organized the work and tracked progress.
- Development Team: Me — implemented and tested the project.

## Product Backlog
| ID | User story | Priority | Status |
|---|---|---|---|
| US1 | As a user, I want to upload an audio file so I can analyze it. | High | Done |
| US2 | As a user, I want to see which target instruments are detected. | High | Done |
| US3 | As a user, I want to view instrument predictions over time. | Medium | Done |
| US4 | As a user, I want to download prediction results as a CSV. | Medium | Done |

## Sprint Plan
- Sprint goal: Document and demonstrate the existing Streamlit instrument-detection project.
- Sprint duration: Individual project; work completed over the project development period.
- Selected backlog items: Audio upload, instrument detection, timeline display, and CSV export.

## Daily Scrum Notes
- This was an individual project, so no formal daily scrum meetings were held.
- Progress was tracked through implementation and testing.
- Blockers: None recorded.

## Sprint Review
- Demonstration: The Streamlit app accepts an audio file and displays instrument predictions and related results.
- Feedback: No formal sprint review was held.

## Sprint Retrospective
- What went well: The project includes an end-to-end audio analysis workflow.
- What could improve: Track tasks and testing outcomes more consistently during development.
- Action items: Maintain a backlog and record progress for future iterations.
